# v0.9.2 upgrade fidelity — design

Approved through the v0.9.2 contract and MF1 Gate 2 on 2026-09-02.

## Public surface

- `setup.sh` keeps its existing flags and writes `agent-config.lock.json` only
  after a successful fresh, merge, or overwrite operation.
- Upgrade plans classify overwrite-managed files as `SAME`, `STALE-MANAGED`,
  `CUSTOMIZED-MANAGED`, or `LEGACY`.
- Later slices add `--prune`; it is valid only with `--merge`.

## Stored format

```json
{
  "schema_version": 1,
  "template_version": "0.9.2",
  "hosts": ["claude"],
  "files": {
    ".claude/agents/backend-dev.md": {
      "template_version": "0.9.2",
      "sha256": "<64 lowercase hex characters>"
    }
  }
}
```

Keys and paths are sorted. Paths are target-relative and restricted to regular,
overwrite-managed files. The lock, user-owned files, local files, symlinks,
design-system files, and merge-managed settings are excluded.

## Compatibility and performance

- Existing answers and setup flags retain their behavior. v0.9.1 targets have
  no baseline, so differing managed files are `LEGACY` until explicitly replaced.
- Classification is one SHA-256 pass per managed file: linear in rendered bytes,
  with no dependency beyond Python's standard library.

## Edge cases

- Missing, malformed, unsupported, absolute, traversing, symlinked, or invalid
  lock state cannot authorize overwrite or deletion.
- Kept stale/customized files retain their old baseline; added, explicitly
  overwritten, and current-identical files advance.
- Preview and abort never write state. Lock replacement is atomic.
- Empty file maps and interrupted temporary writes remain valid or leave the
  previous lock intact.

# claude-config-template — v0.4.0 Refactor Plan

**Status:** approved-in-principle, pre-implementation
**From:** v0.3.2 → v0.4.0 (with an interim v0.3.3 safety release)
**Owner:** Juan Trujillo (@JuanTrujilloDev)
**Last updated:** 2026-06-05

This is the working plan for the v0.4.0 refactor. It captures every change, the
decisions made so far, the ones still open, and the phase-by-phase execution
order. Implementation follows this doc; if reality diverges, we update the doc
first.

---

## 0. Context & sources

- The refactor is driven by the v0.4.0 handoff brief plus real-world failure
  signal (a colleague's `.claude/` got wiped by `/setup-template`).
- The architectural spine is lifted from the **Uncle Bob SDD harness**:
  [betta-tech/harness-sdd @ `uncle-bob-harness`](https://github.com/betta-tech/harness-sdd/tree/uncle-bob-harness).
  Key ideas we're adopting: a single human approval gate on an executable
  contract *before* production code, one feature at a time, state-on-disk (not
  chat), and a `judge` whose review is "the whole game."

---

## 1. Goals (the six outcomes)

1. **Non-destructive setup.** `/setup-template` and `setup.sh` are merge-first,
   ask-first. They can never silently erase an existing `.claude/`.
2. **Advisory, not mandatory.** "Prefer agents," not "MUST use agents." Hooks
   guide rather than block — except the safety-critical branch hard-block.
3. **Clear SDD + TDD orchestrated workflow.** Task in → mini-features out →
   optional test-first gate → judge review → micro-commits.
4. **Fewer, sharper agents and commands.** PMO instead of PO+PM. Judge instead
   of code-reviewer. `/spec` consolidates the idea+sow+plan flow.
5. **Cleaner repo structure.** No manual sync between root and `plugin/` copies.
6. **Backwards-compatible in spirit.** Anyone on a v0.3.x rendered config can
   bump without pain.

---

## 2. Decisions

### Locked

- **§4 structure → Approach #1 (mirror script + CI guard).** Root stays the
  canonical source. A `scripts/sync-plugin.sh` performs the mirror into
  `plugin/`; CI fails any PR where `plugin/` has drifted from canonical.
  `SYNC_NOTE.md` is replaced by a one-line pointer to the script. No submodules,
  no symlinks, both install paths keep working.
- **Design patterns in specs.** When a spec/feature describes something
  technical, the spec author names an applicable design pattern (Strategy,
  Factory, Adapter, Repository, Observer, …) with a one-line *why*, and the
  implementer treats it as part of the contract. **Guardrail:** pattern only
  when it *reduces* complexity for a real, present need — never speculative
  pattern-sprinkling. This sits beside Simplicity First / YAGNI, not against it.
- **Interim release.** Phase 1 (§3 + §5) ships as **v0.3.3** before any
  architecture work, so the two real fixes land fast and independently.

### Open (resolve before Phase 2 — I have a recommendation for each)

| # | Decision | Recommendation | Why |
|---|----------|----------------|-----|
| D1 | Contract format: Gherkin `.feature` vs markdown Given/When/Then | **Markdown spec with a structured "Acceptance Scenarios (G/W/T)" section**; offer real Gherkin as an opt-in flag | Full `.feature` only pays off if you wire a Cucumber/behave runner — most template users won't. Markdown G/W/T gives ~90% of the contract clarity with zero new tooling, across all 4 stacks. |
| D2 | Mutation testing | **Opt-in flag, OFF by default** (`enforce_mutation_testing`, or per-feature `mutation: true`) | Compute-heavy and language-specific (mutmut/cosmic-ray, Stryker). Keep the template light; preserve the harness's best idea as an option for teams that want it. |
| D3 | Agent names | `orchestrator`, `pmo`, `judge` (rename of `code-reviewer`) | See roster table in §4. Confirm before any agent file is written. |

---

## 3. Constraints

- **macOS bash 3.2 compat is non-negotiable.** No `declare -A`, no `mapfile`, no
  post-3.2 bashisms. Python3 is allowed (already required).
- **Both install paths must keep working** — `/plugin install` and clone +
  `setup.sh`. (§4 #1 preserves both.)
- **MIT OSS, real users.** Breaking changes are acceptable for the v0.4.0 jump
  when they buy clear value, but the upgrade path must be documented.
- **Don't run git against the local repo from automation.** Inspect files
  freely; commits, tags, and pushes are Juan's to run (avoids
  `.git/index.lock` lockouts).

## 4. Target architecture — SDD + TDD orchestration

### The spine (from the harness)

```
task in
  → [pmo]          converse + decompose → spec + mini-features (feature_list)
  → [pmo]          distill each feature → acceptance contract (G/W/T)
  → ⏸  GATE 1 (human): approve the contract
  → [orchestrator] feature → in_progress; optionally:
       → ⏸  GATE 2 (human, if TDD): approve tests-first
  → [backend-dev | frontend-dev | ui-designer]  implement the feature
  → [judge]        review code + tests ("the whole game")
  → [security-reviewer]  when auth/permissions/data touched
  → (optional) [mutation-tester]  validate the tests bite
  → micro-commit to working branch
  → done
```

One feature at a time. State lives on disk; subagents write files and return a
one-line reference (the harness "anti-telephone" rule).

### Mapping to Juan's 10-step flow

| Step | Juan's flow | Where it lives |
|---|---|---|
| 1 | Task in (Trello/Plane/Jira or direct) | `orchestrator` ingests; optional tracker MCP pull |
| 2 | PMO creates mini-features (subtasks) | `pmo` writes spec + `feature_list` |
| 3 | Subtasks-in-tracker vs comment-on-task; either way a local spec file | `pmo` asks; always writes local spec/contract |
| 4 | PMO can create "source of truth" tasks for other devs | `pmo` (tracker MCP) |
| 5 | Spec approved → features ready | GATE 1 |
| 6 | Apply TDD? If yes, tests first → user approves | optional GATE 2 |
| 7 | Implementer launches the right technical agent per feature | `orchestrator` → `backend-dev`/`frontend-dev`/`ui-designer` |
| 8 | Judge reviews code + tests | `judge` (+ `security-reviewer`) |
| 9 | Tests green, user approves, micro-commits to working branch | per-feature loop |
| 10 | Done | `feature_list` → done |

### Artifacts & state-on-disk

| File | Written by | Holds |
|---|---|---|
| `docs/specs/<slug>.md` | `pmo` | Conversed spec: purpose, contract, decisions + *why*, **design notes** |
| `docs/specs/<slug>.contract.md` (or `.feature` if D1=Gherkin) | `pmo` | Acceptance scenarios (G/W/T) — the signed contract |
| `feature_list.json` | `orchestrator` | State machine: `pending → spec_ready → in_progress → done / blocked` |
| `docs/progress/<slug>.tdd.md` | implementer | TDD log + `scenario → test` map (when TDD on) |
| `docs/progress/<slug>.judge.md` | `judge` | Review verdict + checkpoints |
| `docs/progress/<slug>.mutation.md` | `mutation-tester` | Mutation score (when enabled) |

(Exact paths are a Phase 2 detail; keep them under `docs/` so they version cleanly.)

### Agent roster (before → after)

| v0.3.2 (7) | v0.4.0 (proposed) | Change |
|---|---|---|
| `pm` + `po-manager` | **`pmo`** | Merge: decomposition + briefs/specs + contract authoring + tracker integration |
| — | **`orchestrator`** | New: coordinates the flow, guards gates, never edits `src/`/`tests/` (= harness `craftsman_lead`, = Juan's "implementer" coordinator) |
| `backend-dev` | `backend-dev` | Keep (technical specialist / implementer) |
| `frontend-dev` | `frontend-dev` | Keep |
| `ui-designer` | `ui-designer` | Keep |
| `code-reviewer` | **`judge`** | Rename; reviews code **and** tests |
| `security-reviewer` | `security-reviewer` | Keep |
| — | `mutation-tester` *(optional, D2)* | Only if mutation testing is enabled |

Net: still ~7 core agents, but re-cut around the SDD flow.

### Design patterns in specs (the new requirement)

- **`pmo` / spec authoring:** every technical feature gets a **Design notes**
  block. If a known pattern fits, name it + one-line why. If none fits, say so
  explicitly ("no pattern needed — single call site").
- **`backend-dev` / `frontend-dev`:** honor the named pattern; if the spec
  named none but the problem clearly matches one, apply it and note it.
- **`principles.md`:** add a balanced line — "Reach for a known design pattern
  when the problem matches one and it reduces complexity; never impose patterns
  speculatively (YAGNI wins)." Reinforced by the existing `backend-dev` gotcha
  about not wrapping a single call site in a `*Service` class.

## 5. Phase plan

### Phase 1 — v0.3.3 (ship first, zero architecture)

Well-specified, high-value, independently shippable. Edits land in **both** root
canonical files and `plugin/` copies (the dup that §4 kills later).

**§3 — colleague's PR feedback, generalized for the template**

- [ ] `agent-enforcement.sh`: agent-gating check → **advisory, exits 0** (prints
      guidance, never blocks). The `CLAUDE_AGENT_ACTIVE=1` path was never set by
      the runtime, so it blocked every non-trivial edit — that whole gate goes
      advisory.
- [ ] `agent-enforcement.sh`: **branch hard-block stays** (exit 2), but
      generalized from hardcoded `main`/`master` to a user-configurable list,
      e.g. `CLAUDE_CONFIG_PROTECTED_BRANCHES="main,qa,prod"` (default `main`).
- [ ] `auto-format.sh`: drop per-edit `black`/full-format; run only **targeted
      `ruff --fix`** inline. Full format moves to the Definition of Done.
      Surface formatter errors to stderr instead of `|| true` swallowing them.
- [ ] Triviality fast-path recalibrated: ≤50 lines **and** ≤1 new `def`/`class`
      passes silently (a single small helper no longer trips the advisory).
- [ ] New **`/fix`** command: small, scoped change — skips brief/plan and the
      formal Design First artifact for an obvious root cause, but keeps the full
      Definition of Done (mandatory `code-reviewer`, `security-reviewer` when
      relevant).
- [ ] **Design First carve-out** in `backend-dev` + the technical specialists:
      changes < ~30 lines with no new model/migration/endpoint may skip the
      formal design artifact.
- [ ] Close the specialist gap: add a shared **"Before you finish"** DoD /
      reviewer / branch-discipline pointer to every specialist agent.
- [ ] `settings.json`: move `git commit` and `git checkout` from `ask` → `allow`
      (low-risk, high-frequency). `git push`, `gh pr *`, and dependency installs
      stay `ask`.
- [ ] `CLAUDE.md`: "**prefer agents**" instead of "MUST"; document `/fix`;
      describe the advisory hook + black-in-DoD-not-per-edit formatting.

**§5 — non-destructive setup (the urgent one)**

The current "don't overwrite without asking" rule lives in *command prose*,
which is skippable — that's how the wipe happened. Fix: move the guard **into
the renderer** so it can't be bypassed.

- [ ] `setup.sh` preflight detects existing config before any write: `.claude/CLAUDE.md`
      **and** root `CLAUDE.md`, `.claude/settings.json`, and
      `.claude/{agents,commands,hooks,rules}/`.
- [ ] Print a **diff** of what would change.
- [ ] Require an explicit mode — `--merge` / `--overwrite` / `--abort` — and
      default to abort if none is given non-interactively.
- [ ] **Merge strategy** for `settings.json`: union of
      `permissions.allow`/`deny`/`ask`; additive merge of `hooks`.
- [ ] **Never touch** `.claude/settings.local.json` (per-user, gitignored).
- [ ] If both `CLAUDE.md` locations exist with **different** content, surface it
      and ask.
- [ ] `setup-template.md` updated to describe the now-enforced behavior (prose
      is backup, not the guard).

**Phase 1 exit / smoke:** all 4 examples render clean (zero leftover
placeholders); `settings.json` parses; hooks register; a dry-run of
`setup.sh` against a repo with an existing `.claude/` refuses to clobber and
shows a diff.

## 6. Verification (per phase)

- **Every phase:** render all 4 examples → grep for unrendered `{{` / `<!-- requires`;
  `python3 -c 'import json,sys; json.load(open(...))'` on each `settings.json`;
  confirm hooks/commands/agents are discoverable.
- **Phase 1 specifically:** simulate the wipe scenario — run `setup.sh` against a
  fixture repo that already has a populated `.claude/` and assert nothing is
  overwritten without an explicit mode.
- **Phase 2:** dry-run the SDD flow on a toy feature; confirm the human gate
  actually halts and that artifacts land on disk.
- **High-stakes steps:** use a subagent to independently verify (diff review,
  settings-merge correctness).

## 7. Deliberately NOT changing

- Parallel specialist investigation (the Explore fan-out pattern).
- The mandatory review step (now `judge`).
- The environment-branch **hard block** (generalized, not removed).
- Micro-PR limits (≤12 files / <3000 LOC).
- Both distribution paths (plugin + clone).
